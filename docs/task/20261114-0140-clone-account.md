## Description

Several accounts often share one SSH key and differ in the user name only. Creating them means pasting the same private key again each time, and the stored key cannot be copied out without a reveal.

- `POST /admin/api/accounts` accepts `clone_from` (an account id). Secrets left blank in `credentials` are taken from that account on the server, like blank secrets on an update keep the stored value. The kinds must match.
- The account dialog gets a Clone action: a create form prefilled with the source's non-secret fields; secrets stay blank and are kept unless typed.
- Step-up applies as for any create; the audit entry names the source.

Acceptance:
- A clone of an ssh-key account with another user name signs in to a target with the source's key.
- Cloning across kinds or from a missing account is refused with 422.
- A secret typed in the clone form replaces the copied one.
- English and zh-CN strings.
